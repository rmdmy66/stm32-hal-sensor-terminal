# STM32F103C8T6 多通道数据采集终端

基于 STM32 HAL 与 FreeRTOS 的嵌入式数据采集、处理与通信终端。系统以 `STM32F103C8T6` 为主控，通过定时器触发 ADC 与 DMA 完成多通道采样，使用 I2C 读取 SHT30 温湿度，并经 USART1 以自定义二进制帧协议上传至上位机，实现数据解析、CSV 记录、实时曲线与异常诊断。

项目重点不是简单堆叠外设，而是在 **64 KB Flash / 20 KB SRAM** 的资源约束下，构建一条具备确定性采样、任务解耦、错误恢复和可量化验收指标的完整数据链路。

## 项目亮点

- **确定性采集链路**：使用定时器触发 ADC，DMA 双缓冲搬运数据，避免在中断中执行计算和阻塞操作。
- **RTOS 任务解耦**：采集、处理、通信、显示和监控分别运行在独立任务中，通过队列传递缓冲区索引，降低耦合和拷贝开销。
- **可恢复的串口协议**：自定义帧包含帧头、长度、命令、序号、CRC16 和帧尾；状态机解析器支持粘包、半包、错帧计数和自动重新同步。
- **面向故障设计**：覆盖传感器超时重试、I2C 总线共享保护、队列溢出统计、任务心跳、独立看门狗和栈余量监测。
- **软硬件协同验证**：提供纯 C 协议实现、主机侧回归测试，以及支持自测、串口解码、CSV 存储和实时绘图的 Python 工具。

## 系统架构

```text
        SHT30 ──I2C1──┐
      电位器 ──ADC1───┤
                       ▼
              ┌──────────────────┐      USART1 / 115200-8-N-1      ┌──────────────────┐
              │ STM32F103C8T6    │ ─────────────────────────────► │ Python 上位机     │
              │ HAL + FreeRTOS   │ ◄───────────────────────────── │ 解析 / CSV / 曲线 │
              └────────┬─────────┘                                └──────────────────┘
                       │ I2C1
                    OLED（可选）
```

数据流：`定时器触发 → ADC + DMA → 采集任务 → 处理任务 → 协议组帧 → USART1 → 上位机`。

## 核心功能

- **模拟量采集**：ADC1 12 位采样，目标采样率 1 kHz，定时器硬件触发，DMA 双缓冲。
- **环境数据采集**：通过 I2C1 读取 SHT30 温湿度，支持超时、重试、在线状态标记和总线恢复。
- **FreeRTOS 调度**：多任务划分，队列解耦采集与处理，互斥量保护 SHT30 与 OLED 共享的 I2C 总线。
- **可靠通信**：自定义二进制帧协议，CRC16 校验，序号用于丢帧定位，异常帧可统计并自动重新同步。
- **上位机工具**：Python 实现帧构建、解析、自测、串口监听、CSV 记录和实时曲线。
- **运行监控**：采集队列溢出计数、协议错误计数、任务栈高水位、任务心跳和独立看门狗。

## 关键设计

### 数据采集与缓冲

- 定时器更新事件触发 ADC 转换，DMA 以循环模式写入双缓冲。
- DMA 半传输/传输完成中断只记录缓冲区索引和时间戳，不执行浮点运算或串口输出。
- 采集任务按半缓冲或全缓冲粒度取数，完成电压换算和滤波后送入处理队列。
- 1 kHz 是采样率，不等同于 1 kHz 上报率；115200 波特率下目标上报 50-100 Hz，原始高速数据通过本地缓冲、抽取或提高波特率处理。

### FreeRTOS 任务划分

| 任务 | 优先级 | 触发方式 | 职责 |
|---|---:|---|---|
| `acq_task` | 4 | 1 ms / DMA 事件 | 管理 ADC 缓冲，读取 SHT30（1 Hz） |
| `proc_task` | 3 | 队列事件 | 滤波、单位换算、状态判别、数据打包 |
| `comm_task` | 3 | 队列 / 串口事件 | 发送数据帧、解析命令、维护序号 |
| `disp_task` | 1 | 200 ms | 刷新 OLED 状态页 |
| `mon_task` | 1 | 1 s | 检查任务心跳、栈余量和错误计数，健康时喂狗 |

关键约束：

- 中断服务函数只做最短路径处理，不使用动态内存分配。
- SHT30 与 OLED 共用 I2C1，访问前获取互斥量，避免总线竞争。
- `mon_task` 只有在关键任务心跳正常时才喂独立看门狗，避免系统卡死后仍被误喂狗。

### 串口帧协议

| 字段 | 长度 | 说明 |
|---|---:|---|
| 帧头 | 2 B | 固定 `AA 55` |
| 负载长度 | 1 B | `0-64` 字节 |
| 命令字 | 1 B | 区分心跳、数据、配置等操作 |
| 序号 | 1 B | `0-255` 循环，用于应答和丢帧定位 |
| 负载 | N B | `0-64` 字节 |
| CRC16 | 2 B | Modbus CRC16，小端发送 |
| 帧尾 | 2 B | 固定 `0D 0A` |

帧总长度为 `9 + N`。CRC16 参数为初始值 `0xFFFF`、多项式 `0xA001`，覆盖“长度 + 命令 + 序号 + 负载”。解析器采用逐字节状态机，能够处理粘包和半包；长度、CRC 或帧尾错误会分别计数，并回到帧头状态重新同步。

示例：命令 `0x01`、序号 `0x01`、空负载的完整帧为：

```text
AA 55 00 01 01 B1 90 0D 0A
```

### 可靠性设计

- **传感器异常**：I2C 操作设置超时；连续失败后标记离线并尝试重新初始化，恢复后自动重新上线。
- **协议异常**：CRC、帧尾和长度错误独立计数，错误帧丢弃后从下一个 `AA 55` 重新同步。
- **任务异常**：采集与通信任务维护心跳计数，监控任务发现超时后记录故障，不盲目喂狗。
- **资源监控**：统计队列溢出、栈高水位和 CPU 空闲时间，为任务栈与优先级调整提供依据。
- **长稳验证**：通过连续运行测试观察重启、丢帧、内存和错误计数变化。

## 硬件平台

| 功能 | 外设 | 引脚 | 说明 |
|---|---|---|---|
| 调试下载 | SWD | `PA13 / PA14` | SWDIO / SWCLK |
| 串口通信 | USART1 | `PA9 / PA10` | TX / RX，接 USB-TTL |
| 温湿度与 OLED | I2C1 | `PB6 / PB7` | SHT30 地址 `0x44`，OLED 地址 `0x3C` |
| 模拟量输入 | ADC1_IN0 | `PA0` | 电位器输出，输入不得超过 3.3 V |
| 状态指示 | GPIO | `PC13` | 板载 LED，低电平点亮 |
| 用户按键 | GPIO | `PA1` | 内部上拉，按下接地 |

## 快速开始

### 1. 运行协议自测

```bash
python -m pip install -r host/requirements.txt
python host/frame_tool.py --self-test
python host/frame_tool.py --demo
```

### 2. 连接串口并记录数据

```bash
python host/frame_tool.py --port COM5 --baud 115200 --csv capture.csv --plot
```

`--plot` 和 CSV 记录为可选功能；只做协议解析时可以不安装 matplotlib。

### 3. 创建 STM32 工程

在 STM32CubeMX 中选择 `STM32F103C8Tx`，按板载晶振配置 HSE/PLL 至 72 MHz，并完成以下外设配置：

- SWD 调试接口；
- USART1，`115200-8-N-1`；
- I2C1，连接 SHT30 和 OLED；
- ADC1_IN0，定时器触发，DMA 循环模式；
- 独立看门狗 IWDG；
- FreeRTOS，使用 CMSIS-RTOS v2 或原生 API。

将 `firmware/protocol` 加入头文件搜索路径，并把 `frame.c` 加入编译。

### 4. 运行主机侧检查

```powershell
powershell -ExecutionPolicy Bypass -File test/check_c.ps1
```

## 验收指标

以下为设计验收目标；实机测试完成后补充原始数据、测试条件和复现记录。

| 类别 | 目标指标 |
|---|---|
| ADC 采样 | 1 kHz 连续采样，10 分钟采集无队列溢出、无丢样本 |
| 实时性 | 中断服务短小，DMA 回调不阻塞；采集到处理队列的延迟可测量 |
| 串口通信 | 115200-8-N-1 下稳定上报；序号连续，丢帧可定位 |
| 协议健壮性 | 随机字节流中不崩溃；错误帧被计数，并在下一帧重新同步 |
| 传感器恢复 | 掉线后 1 s 内标记离线，恢复后 2 s 内重新上线 |
| RTOS 资源 | 关键任务栈高水位不低于 30%，CPU 空闲时间可统计 |
| 长时间运行 | 24 小时连续运行无看门狗复位，错误计数与内存占用稳定 |
