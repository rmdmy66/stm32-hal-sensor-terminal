# 四周计划（STM32F103C8T6 + HAL，3 周核心 + 1 周缓冲）

原则：每天结束都要有一个能跑的版本。做不完就砍功能，不要跳步骤。

## 第 0 周：环境和骨架（2-3 天）

- 安装/打开 STM32CubeIDE，新建 `STM32F103C8Tx` 工程，使用 HAL。
- 点亮 LED，按键控制 LED。
- 用 USB-TTL 打通 USART1，`printf` 每 500 ms 输出一行日志。
- 加 HardFault 处理，故意制造一个错误，确认能打印出错位置。
- `git init`，第一次提交。

验收：

- 上电 3 秒内看到日志。
- 按键能翻转 LED。
- 故意写非法地址，能看到 HardFault 信息。

资源基线：

- Flash 64 KB、SRAM 20 KB。
- 先不用 FreeRTOS，不加 OLED，不用浮点 printf。
- 代码优化优先 `-Os`。

## 第 1 周：外设打通

第 1-2 天：

- UART + DMA + IDLE 中断，收不定长数据。
- USART1：PA9/PA10；RX DMA 用 DMA1 Channel5，TX DMA 用 DMA1 Channel4。
- 环形缓冲区，单生产者单消费者。
- 串口回显测试：PC 发什么，板子回什么。

第 3-4 天：

- ADC + 定时器触发 + DMA 双缓冲，1 kHz 采样。
- ADC1_IN0（PA0），TIM2 触发，DMA1 Channel1 搬运。
- 把原始值换算成毫伏，打印最小/最大/平均值。
- 用逻辑分析仪看定时器触发和 DMA 波形。

第 5 天：

- I2C1（PB6/PB7）读 SHT30，加超时、重试、错误计数。
- 拔掉 SHT30，程序不能卡死。

第 6-7 天：

- OLED 显示温度、湿度、ADC 值。
- 整理错误计数：UART 错帧、I2C 超时、ADC 溢出。

验收：

- 1 kHz 采样连续跑 10 分钟，不丢样本。
- 拔掉 SHT30 后，日志有错误计数，程序继续跑。
- 逻辑分析仪能看到 I2C 的 ACK/NAK。

## 第 2 周：RTOS 和协议

第 1-2 天：

- 建三个任务：`acq_task`、`proc_task`、`comm_task`。
- 队列传数据，互斥量保护 I2C 总线。
- 中断里只通知，不做事。
- FreeRTOS 堆先从 6-8 KB 开始，任务栈按高水位调整。

第 3-4 天：

- 接入 `firmware/protocol/frame.c`。
- 实现帧解析状态机、CRC16、ACK、超时重传。
- 定义命令：心跳、数据上报、设置周期、设备信息。

第 5-7 天：

- Python 上位机：串口读取、解析、CSV、实时曲线。
- 连续发 1000 帧，统计 CRC 错误和丢帧。
- 115200 波特率下按 50-100 Hz 上报，不要每毫秒发一帧。

验收：

- 上位机能看到实时曲线。
- 1000 帧 0 误判。
- 拔插串口后能恢复。

## 第 3 周：可靠性和交付

第 1 天：

- 独立看门狗 + 多任务心跳。
- 人为卡死一个任务，确认系统会复位。

第 2 天：

- 参数存内部 Flash，带 CRC 和双备份。
- 上电读取参数，掉电不丢。

第 3-4 天：

- 24 小时老化测试，记录重启次数、错误计数、栈余量、CPU 占用。
- 修掉最严重的三个问题。

第 5-7 天：

- 写 README：架构图、指标表、故障复盘。
- 录 1 分钟演示视频。
- 写项目总结、演示说明和复盘。

验收：

- 24 小时 0 重启。
- 指标表有真实数字。
- 演示视频能完整走一遍：上电 -> 采集 -> 上位机曲线 -> 拔传感器 -> 恢复。

## 第 4 周：缓冲和加分项

优先顺序：

1. 修 bug，补测试。
2. OLED 美化。
3. STOP 模式 + IDD 电流测量。
4. W25Q64 日志。
5. Modbus RTU 或 OTA（时间够再做）。

## 如果落后，砍什么

保留：

- UART + DMA + 环形缓冲。
- ADC + DMA。
- FreeRTOS 任务 + 队列 + 互斥量。
- 帧协议 + CRC16。
- Python 上位机。
- 看门狗 + 错误计数。

可以砍：

- OLED。
- 内部 Flash 参数。
- 低功耗。
- W25Q64。
- Modbus/OTA。

## 要记录的指标

| 指标 | 怎么测 | 目标 |
|---|---|---|
| ADC 采样率 | 定时器计数/示波器 | 1 kHz ±1% |
| 丢样本数 | DMA 半满/全满计数 | 10 分钟 0 |
| 串口帧率 | 上位机统计 | 50-100 帧/秒（115200） |
| CRC 错误率 | 上位机统计 | 1000 帧 0 |
| 24 小时重启次数 | 日志开头的 boot 计数 | 0 |
| 栈余量 | `uxTaskGetStackHighWaterMark` | >30% |
| CPU 占用 | `vTaskGetRunTimeStats` | <50% |
| 代码大小 | `.map` 文件 | 记录即可 |

## F103C8T6 资源预算（起步值）

| 项目 | 建议起点 | 说明 |
|---|---:|---|
| FreeRTOS heap | 6-8 KB | 不够时再增加，先看 malloc failed |
| acq_task 栈 | 256 words | 约 1 KB |
| proc_task 栈 | 256 words | 滤波和打包会增加栈 |
| comm_task 栈 | 256 words | 协议解析和发送 |
| disp_task 栈 | 192 words | OLED 刷新 |
| mon_task 栈 | 192 words | 统计和喂狗 |
| UART 环形缓冲 | 256-512 B | 先小后大 |
| ADC 双缓冲 | 2 × 128 个 uint16_t | 约 512 B |

原则：先用保守值跑通，再用 `uxTaskGetStackHighWaterMark` 和高水位数据调整。不要一上来开大缓冲区。
