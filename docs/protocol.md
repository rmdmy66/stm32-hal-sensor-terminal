# 帧协议

目标：简单、可调试、能处理粘包和半包。PC 和 MCU 使用同一套规则。

## 帧格式

| 字段 | 长度 | 说明 |
|---|---:|---|
| 帧头 | 2 | 固定 `0xAA 0x55` |
| 长度 | 1 | 负载长度，0-64 |
| 命令 | 1 | 命令字 |
| 序号 | 1 | 0-255 循环，用于 ACK 和重传 |
| 负载 | N | 0-64 字节 |
| CRC16 | 2 | 小端，覆盖“长度 + 命令 + 序号 + 负载” |
| 帧尾 | 2 | 固定 `0x0D 0x0A` |

总长度 = `9 + N`。

## CRC16

使用 Modbus CRC16：

- 初始值 `0xFFFF`
- 多项式 `0xA001`（反向）
- 输入和输出都不反转

标准测试向量：字符串 `"123456789"` 的 CRC 是 `0x4B37`。

## 命令字

| 命令 | 方向 | 负载 | 说明 |
|---:|---|---|---|
| `0x01` | PC -> MCU | 空 | 心跳，MCU 回同样的序号 |
| `0x02` | MCU -> PC | 12 字节 | 数据上报 |
| `0x03` | PC -> MCU | 2 字节 | 设置上报周期，单位 ms，小端 |
| `0x04` | PC -> MCU | 空 | 读设备信息 |
| `0x05` | PC -> MCU | 1 字节 | 1 开始上报，0 停止 |

数据上报负载（12 字节，小端）：

| 偏移 | 类型 | 含义 |
|---:|---|---|
| 0 | `uint32_t` | 系统 tick，单位 ms |
| 4 | `int16_t` | ADC 电压，单位 mV |
| 6 | `int16_t` | 温度，单位 0.01 摄氏度 |
| 8 | `uint16_t` | 湿度，单位 0.01 %RH |
| 10 | `uint16_t` | 标志位：bit0 传感器在线，bit1 看门狗复位 |

## 解析状态机

```text
HEAD1 -> HEAD2 -> LEN -> CMD -> SEQ -> PAYLOAD -> CRC_LO -> CRC_HI -> TAIL1 -> TAIL2 -> OK
```

错误处理：

- 长度大于 64：丢弃，`length_error_count++`。
- CRC 不匹配：丢弃，`crc_error_count++`。
- 帧尾不对：丢弃，`tail_error_count++`。
- 任何错误后回到 `HEAD1`，下一个 `0xAA` 重新同步。

## 示例

命令 `0x01`，序号 `0x01`，空负载：

```text
AA 55 00 01 01 B1 90 0D 0A
```

CRC 计算范围是 `00 01 01`，结果是 `0x90B1`，小端发送为 `B1 90`。

## 设计取舍

- 用固定帧头而不是“长度开头”，方便从任意位置重新同步。
- 用 CRC16 而不是累加和，能发现多位错误。
- 用序号做 ACK，PC 可以判断哪一帧丢了。
- 负载上限 64 字节，避免大缓冲区占用 RAM。
